# NightVeil 自主迭代协议

（实例化自上级模板 ../自主迭代.md，按 2026-09-08 grilling 共识调整：无 popup、esbuild 构建、双层验收场、防拷贝纪律。里程碑跟踪见 docs/MILESTONES.md。）

## 项目概况
- 项目根：本目录（`./`）
- 源码：`./src/`（ES Modules，详见 docs/adr/0001）
- 扩展根目录：`./extension/`（esbuild 产物，`chrome://extensions` 以"加载已解压的扩展程序"装入）
- 入口：`manifest.json` / `content.js` / `background.js` / `options.html`
- **无 popup**：点击工具栏图标 = 全局切换 Light/Dark（忠实原版，见 docs/adr/0003）
- 目标页面：本地验收页 `http://localhost:8123/*.html`（`tests/fixtures/` 托管）；里程碑收尾另做真实站点抽查（清单见 docs/MILESTONES.md）

## 构建与验证准备
1. 改代码后先 `npm run build`（或常开 `npm run watch`），产物进 `extension/`
2. 验收页服务：`npm run fixtures`（端口 8123）
3. 验证一律通过 `/tabbit` 完成：重载扩展 → 打开验收页 → 截图 → 读 console

**已知环境限制（2026-09-09 M0 验收发现）**：tabbit workspace 拦截 `chrome://`、`chrome-extension://`、`file://` 导航，且扩展 service worker 不在任务 context 内、console 无法捕获。因此：
- 扩展加载/重载与卡片 Errors 检查 → 用户人工操作（或确认一次后依赖 content script 存活作为重载证据）
- options 等扩展页面 UI 验证 → 把 `extension/` 内对应产物临时拷入 `tests/fixtures/` 经 http 挂载断言，验完即删
- SW 证据 → 卡片无 Errors + 依赖 SW 的功能行为（M1 起有了消息机制后可功能性验证）

## 验收标准（Definition of Done）
每次改动后，以下条目必须全部通过才算完成：

**通用条目（每轮必查）**
1. [ ] `extension/` 在 chrome://extensions 无报错加载（无红色错误、无黄色警告）
2. [ ] 打开验收页后 content script 正常注入（console 无未捕获异常）
3. [ ] service worker console 无新报错
4. [ ] `tests/` 中已固化的回归测试全部通过

**里程碑条目（当前：M1，进入新里程碑时整体替换本节，旧条目转入回归测试）**
5. [ ] 点击工具栏图标，plain.html 在 Light/Dark 间切换，图标与标题随状态变化
6. [ ] 选择某个 Classic Theme 后刷新页面主题仍生效（持久化）；换选另一主题立即替换
7. [ ] Exclusion List 加入当前域名后该站不再生效；Inclusion Mode 下仅列表内域名生效
8. [ ] options.html 各分区可展开、修改即自动保存、Reset 恢复出厂设置

## 自主迭代协议（/tabbit 循环）
进行任何与 UI、注入逻辑、manifest 相关的修改时，必须严格执行以下循环，禁止"改完就宣布完成"：

1. **修改代码** —— 最小化改动，一次只解决一个问题
2. **执行验证** —— 调用 `/tabbit`，由它完成：
   - 重载未打包扩展
   - 打开目标页面并触发扩展动作
   - 截图 options 页与页面注入效果
   - 读取 service worker 与 content script 的 console
3. **对照验收** —— 将 `/tabbit` 返回的截图和日志，逐条对照上方「验收标准」
4. **判定**：
   - ✅ 全部通过 → 停止迭代，输出简短总结（改了什么、验证结果），并更新 docs/MILESTONES.md 勾选状态
   - ❌ 任一失败 → 分析失败原因，修改代码，回到步骤 2
5. **终止条件**：同一问题连续失败 3 次仍无法解决 → 停止循环，向用户汇报现状、已尝试方案和卡点，等待人工决策

## 迭代纪律
- 每轮改动必须能解释"这一改是为了修复哪条验收失败"
- 禁止同时修改多个无关文件，禁止顺手"重构"未出错的代码
- 不要凭代码推断效果，必须以 `/tabbit` 的实际截图和 console 输出为准
- 修改 `manifest.json`（权限、host_permissions）前必须先向用户说明理由并征得同意
- **防拷贝红线**：实现功能时以行为清单/ADR-0003 为规格来源，不边看原版源码边写代码（勘察阶段已建立的行为理解足够）

## 沉淀回归测试
一个验收条目连续通过 2 轮后，把它固化成 Playwright 测试脚本存入 `./tests/`（跑在 8123 fixtures 服务上），后续每轮迭代结束后自动跑一遍，防止优化 A 弄坏 B。

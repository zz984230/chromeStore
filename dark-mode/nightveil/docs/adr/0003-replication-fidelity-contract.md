# 复刻保真度边界（Replication Fidelity Contract）

任务要求"复刻功能但避免完全 copy（不限于变量名、函数名、代码结构）"。"复刻到什么程度、差异化到什么程度"必须可审计，否则验收没有基线。2026-09-08 经 grilling 访谈敲定如下分界：

| 层面 | 处理方式 |
|---|---|
| 代码架构 / 标识符命名 / 消息协议 / 存储键 / CSS 变量前缀（`--nv-*`） | **全新设计**，与原版无词汇对应 |
| 设置页 UI | 信息架构对应，视觉与文案全新 |
| Adaptive Engine 的 30+ 子选项 | **逐项 1:1 功能对等**，维护"原选项 ↔ 新选项"映射表 |
| 通用主题视觉 / Palette | **原创设计**，仅风格类别与数量对等（见 ADR-0002） |
| 站点主题 | M1 交付 10 个高频站（选择器自写），其余 22 个进 Backlog 分批补齐 |
| 设计层行为（如非包含模式下右键菜单只显示 Exclude） | **忠实照抄**，保证复刻验收基线干净 |
| 原版代码 bug（如开关状态竞态） | **不刻意复刻**——重写自然消除，也不算"修复" |
| 运营功能（欢迎页、卸载跳转、交叉推广、捐赠） | **砍除**；仅保留恢复出厂设置与本地测试页 |

## Consequences

- "复刻完成"的判据 = 原版行为清单逐条通过，而非代码相似度。
- 复刻期不做任何"顺手改良"：已知差评问题全部进 docs/BACKLOG.md，M3 之后按自主迭代协议逐个作为独立可验收的迭代处理。
- 实现功能时以行为清单为规格来源，不边看原版源码边写代码，防止结构被无意识带走。

## 附录：M2 行为清单建档程序（2026-09-13 grilling 补充）

M2 起上述红线细化为「建档关门」程序：任务 0 先行，允许通读原版源码提炼**纯行为描述**（能力面、选项清单、变量语义、边缘行为——不含实现结构与代码细节），产出行为清单 + 原选项↔新选项映射表，经用户审定后关门；此后实现阶段只看文档，不再读原版源码。理由：native.js 的能力面含大量 UI 上不可直接观察的行为（重扫时机、跨域处理、解析格式面），只看 UI 会漏；通读产出纯行为文档后关门，红线仍然干净。

# 字符级高亮:泛化引擎核心而非复制

对比工具的行内差异(字符级高亮)复用自研 Myers 引擎:核心抽取为吃任意序列的 `diffSeq(a, b)`,行级 `diffLines` 与新增字符级 `diffChars` 是两片薄适配层(行=按换行切分,字符=按码点切分)。配对规则照 DiffSuite 的观感蓝本:差异块内第 i 条删除行与第 i 条新增行配对跑字符 diff,落单行整行铺色、不带字符块;合并语义不受配对影响,仍以块为单位。字符级超限(复用 D_CAP)或超长行**静默**降级为整行铺色、不加 banner——字符块是增强层,缺席即回到先前行级观感,不构成诚实性问题(与行级降级必须页面明示不同)。

否决的两条路:复制一份字符版算法——这段代码出过 base 符号错,同一算法存两份即双倍腐烂机会;字符数组 `join('\n')` 后直接喂行级接口——零新码但每次对比做无谓的大字符串分配,且 D_CAP 语义在字符尺度失真。泛化把「引擎=序列差分,行/字符只是切分策略」写进代码,与 0004 的归一化缝正交:归一化器动输入文本,切分策略动 diff 粒度,两缝各自独立演进。

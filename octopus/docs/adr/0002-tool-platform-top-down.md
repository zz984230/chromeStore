# 工具平台:顶层设计壳与契约,移植工具内脏

octopus 不做两个旧项目的机械拼装,而是顶层设计一个工具平台:壳(唯一的 background/popup/options/manifest、工具注册表、消息路由、存储封装、文案聚合)+ 工具契约(声明式接口:id、面板模块、设置 schema、content 注入片段、SW 生命周期钩子、commands、manifest 增量)。**manifest 由构建期从工具声明装配**,第三个工具接入 = 加目录 + 一行注册。两个现有工具的内脏(veil 着色引擎、pace 发现/守速/熔断)作为实现移植到契约后面,不重写——297 个既有测试守住的是行为,行为没变就没有重写的理由。

契约按两个前身验证过的形状(页面注入 + 设置 + 面板 + 快捷键)设计;无页面行为的未来工具把这些槽位留空即可,不为此引入第二套抽象。

## Considered Options

- 目录即工具的极简约定(无契约):本会话早期曾裁定,因「后续还会有其他的功能,要从顶层重新设计」被推翻——第三个工具会重复手接 manifest/路由/面板的全套胶水。
- 连工具内脏一起重写:工期翻倍起步,把已验收行为押给一次没被要求的重写,弃。

# 浏览器扩展自主迭代协议

## 项目概况
- 项目：视频倍速助手 —— 在任意网页调节 HTML5 `<video>` 播放档位的浏览器扩展（Chrome/Chromium 系，Manifest V3）
- 源码目录：`./src/`（esbuild 构建）；扩展根目录：`./extension/`（构建产物，未打包）
- 入口：`manifest.json` / `popup.html` / content script / service worker
- 目标页面：保密观课程视频页（Vue SPA + AliPlayer）：
  `https://www.baomi.org.cn/bmVideo?id=312bc914-8e11-421b-b9bc-e900fe1a4e50&docId=56242300&docLibId=-15&pubId=&siteId=95&doclibId=3&coursePacketId=312bc914-8e11-421b-b9bc-e900fe1a4e50&directoryId=8b6a1343-3212-4934-b609-94c12e6b1a0d&resourceId=7c3d8562-e88b-4bdc-8839-e8b4f1de417d&docIds=56242227&pubIds=42388`
- 参考插件：`./fjhefbhpidlapjcngiojjoclnfldehno/`（已 gitignore，只读）。**功能与逻辑可以复刻；代码禁止照搬**——变量名、函数名、消息协议、代码结构均不得与参考源雷同，命名体系以 `CONTEXT.md` 词汇表为准。涉及与参考插件相同功能区域的改动，任务审查时须人工对照参考源做相似度比对。

## 验收标准（Definition of Done）
每次改动后，以下条目必须全部通过才算完成：
1. [ ] 扩展能在 `chrome://extensions` 无报错加载（无红色错误、无黄色警告）
2. [ ] 打开保密观测试视频页后，content script 正常注入（console 无未捕获异常），popup 能读到当前视频实际档位
3. [ ] popup 滑块/预设调档 → 视频实际播放档位改变，浮标短暂显示（保持模式带 🔒）
4. [ ] 保持模式开启时刷新页面/切换集数，档位自动恢复；保持关闭时不干预新视频
5. [ ] 片头/片尾跳过按规则生效（开始播放时越过片头；临近片尾时循环视频暂停、普通视频跳到结尾）
6. [ ] 自动续播：视频自然结束后能找到并点击"下一节"类按钮；站点自身已连播时不干预
7. [ ] service worker console 无新报错

## 自主迭代协议（/tabbit 循环）
进行任何与 UI、注入逻辑、manifest 相关的修改时，必须严格执行以下循环，禁止"改完就宣布完成"：

1. **修改代码** —— 最小化改动，一次只解决一个问题
2. **执行验证** —— 调用 `/tabbit`，由它完成：
   - 重载未打包扩展
   - 打开目标页面并触发扩展动作
   - 截图 popup 与页面注入效果
   - 读取 service worker 与 content script 的 console
3. **对照验收** —— 将 `/tabbit` 返回的截图和日志，逐条对照上方「验收标准」
4. **判定**：
   - ✅ 全部通过 → 停止迭代，输出简短总结（改了什么、验证结果）
   - ❌ 任一失败 → 分析失败原因，修改代码，回到步骤 2
5. **终止条件**：同一问题连续失败 3 次仍无法解决 → 停止循环，向用户汇报现状、已尝试方案和卡点，等待人工决策

## 迭代纪律
- 每轮改动必须能解释"这一改是为了修复哪条验收失败"
- 禁止同时修改多个无关文件，禁止顺手"重构"未出错的代码
- 不要凭代码推断效果，必须以 `/tabbit` 的实际截图和 console 输出为准
- 修改 `manifest.json`（权限、host_permissions）前必须先向用户说明理由并征得同意
- 涉及参考插件已有功能区域的实现，必须走"人工对照参考源相似度比对"门禁，见「项目概况」

## 沉淀回归测试
一个验收条目连续通过 2 轮后，把它固化成 Playwright 测试脚本存入 `./tests/`，后续每轮迭代结束后自动跑一遍，防止优化 A 弄坏 B。
